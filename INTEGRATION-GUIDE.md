# Runbook — deploy, configure, operate

Plans live in `docs/` (`LAUNCH-PLAN.md`, `SEO-PLAN.md`, `ARCHITECTURE.md`). This file is the how-to.

## 1. Local development

```bash
pip install -r requirements-dev.txt
createdb meridian_dev                      # PostgreSQL 14+ (btree_gist extension is created automatically)
export DATABASE_URL=postgresql://localhost/meridian_dev SECRET_KEY=dev-only-not-secret
python3 build.py                           # generate index.html, pricing.md, robots.txt, sitemap.xml
uvicorn app.main:app --reload              # http://localhost:8000 · /admin · /api/docs (APP_ENV=development only)
TEST_DATABASE_URL=postgresql://localhost/meridian_test pytest
```

Migrations in `migrations/NNN_*.sql` run automatically at start-up (advisory-locked). Never edit an applied
migration in production — add `002_*.sql`.

## 2. Deploy (Render — current host)

Infrastructure is code: `render.yaml` defines a Docker web service (`meridian-chauffeur-skylim`, always on)
and a managed PostgreSQL 16 (`meridian-db`), both in Virginia on Render's private network. The database
accepts no connections from the public internet. Health check: `/healthz`.

1. **Deploys** build from branch `claude/focused-ride-wdxju1`. Auto-deploy on push needs the Render GitHub
   app to have access to this repository (GitHub → Settings → Applications → Render → Repository access).
   If a push does not start a deploy: Dashboard → service → **Manual Deploy → Deploy latest commit**.
2. **Secrets** (`sync: false` in `render.yaml`) are set in Dashboard → service → **Environment**, never
   committed. Generate locally: `python -m app.security new-secret` (TRACKER_PHONE_ID) and
   `python -m app.security hash-password` (ADMIN_PASSWORD_HASH). `SECRET_KEY` is generated by Render.
3. **Domain**: Dashboard → service → Settings → **Custom Domains**; add the DNS records Render shows.
   The HTTPS certificate is automatic. Then set `PUBLIC_BASE_URL=https://<domain>` and redeploy.
4. **Staging → production**: the service runs `APP_ENV=staging` (refuses live Stripe keys, only emails
   addresses in `EMAIL_ALLOWLIST`, API docs hidden). Switch to `production` only when every launch gate in
   `/admin` passes. To keep a permanent staging copy, duplicate the service with its own database.
5. **Backups and rollback**: the paid database has point-in-time recovery — test a restore before launch.
   Roll back a bad deploy from Dashboard → service → **Events → Rollback** (migrations are additive, so
   the previous image keeps working).

`railway.json` is kept so the same Dockerfile can run on Railway if you ever move hosts.

## 3. Stripe

1. Dashboard → Settings → Payment methods: enable **Cards, Apple Pay, Google Pay, Link**. Request **Affirm,
   Klarna, Afterpay** (eligibility is reviewed by Stripe) and the **PayPal** invite. No code change is needed —
   Checkout uses dynamic payment methods. Keep `PAYMENT_METHODS_DISPLAY` in sync with what is on.
2. Developers → Webhooks → endpoint `https://<domain>/api/webhooks/stripe`, events:
   `checkout.session.completed`, `checkout.session.async_payment_succeeded`,
   `checkout.session.async_payment_failed`, `checkout.session.expired`, `charge.refunded`.
   Copy the signing secret to `STRIPE_WEBHOOK_SECRET`.
3. Use a restricted key (`rk_live_…`) with write access to Checkout Sessions and Refunds only.
4. Test in staging with Stripe test cards: success `4242…`, decline `4000 0000 0000 0002`,
   3-D Secure `4000 0025 0000 3155`; cancel at Checkout; replay a webhook from the Dashboard (must say
   `duplicate`/`already_paid`, never double-confirm).
5. Set `PAYMENTS_ENABLED=true`. In production, payment stays off until every launch gate in `/admin` passes.

## 4. Live location (Traccar Client)

1. Install **Traccar Client** (iOS/Android) on the chauffeur's phone.
2. Device identifier → the value of `TRACKER_PHONE_ID`. Server URL → `https://<domain>/api/tracking/osmand`.
   Location accuracy: high; frequency: 10 s; allow location **Always**; disable battery optimisation (Android).
3. `TRACKING_ENABLED=true`, redeploy, then press **En route** in `/admin` before a test drive and watch the
   trip page from a second phone. Lock the phone and drive through a tunnel: the page must turn "stale".
4. Optional in-car tracker (later): add the device to a Traccar server, set `forward.enable=true`,
   `forward.type=json`, `forward.url=https://<domain>/api/tracking/traccar`,
   `forward.header=Authorization: Bearer <TRACCAR_FORWARD_TOKEN>`; set `TRACKER_VEHICLE_ID` to its uniqueId.

## 5. Email (Postmark)

Create a server, verify the sending domain (SPF/DKIM), set `POSTMARK_SERVER_TOKEN` and `EMAIL_FROM`.
Without a token, emails wait in `/admin` → "Emails to send by hand" — nothing is lost.

## 6. Google tags

See `docs/SEO-PLAN.md §5`. Set `GTM_CONTAINER_ID` (or `GA4_MEASUREMENT_ID`) and `GA4_API_SECRET`;
tags are injected at serve time with validated IDs and Consent Mode v2 defaults.

## 7. Daily operation (`/admin`, phone-friendly)

- **New requests**: approve (optionally adjust price with a reason the client sees) or decline.
- **Upcoming trips**: one big button per step — *En route → Arrived → On board → Completed*.
  Tap before driving; never while moving.
- **Availability**: pause instant booking at peak; block personal time.
- **Needs attention**: late payments, refund failures, luggage or child-seat checks.
- **Last 30 days**: funnel, revenue, lost demand, channels; Google Ads conversion CSV.

## 8. Changing content and prices

| Change | Where | Then |
|---|---|---|
| Copy, services, FAQs, amenities, places, luggage guide | `data.py` | `python3 build.py`, redeploy |
| Landing pages (airports, NYC, NJ): words, journeys, FAQs | `landing_pages.py` | `python3 build.py`, `pytest tests/test_seo.py`, redeploy |
| Brand name or logo letter | `data.BRAND` | `python3 tools/make_images.py`, `python3 build.py` |
| Pricing inputs, hourly rate, launch offer | `data.PRICING` | `python3 tools/rate_model.py --write`, review, `python3 build.py` |
| Layout | `marketing/` | `python3 build.py` |
| Styles / behaviour | `static/site.css`, `static/site.js`, `static/tokens.css` | redeploy |
| Booking rules | `app/domain/` (pure, unit-tested) | `pytest` |
